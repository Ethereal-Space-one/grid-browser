# G1｜浏览器内核决策记录（进行中）

> 更新：2026-11-04。依据主计划 M0/M1 与技术方案 §2.2。先用 Electron/Chromium 原型验证核心动线的用户价值；独立 fork 须另作 ADR 并证明维护能力。

下一阶段的[架构调查](./ARCHITECTURE_RESEARCH_2026-11-04.md)和[ADR 0002 提案](./adr/0002-next-stage-architecture.md)建议先模块化现有 Electron/TypeScript 载体，通过请求状态、动作约束、实际包与用户任务实验再选最终内核。此建议不等于 G1 已通过。

## 选择要回答的问题

Grid 先验证自主查询、A/B 阅读和可控 Agent 的用户价值。若选择独立浏览器，内核还须支持真实网页与登录态、主流站点、媒体播放与实时通信、PDF/打印、下载上传、Passkey、扩展生态、浏览器主进程动作闸门、安全更新和跨平台构建。横向能力见 [浏览器基建矩阵](./BROWSER_FOUNDATIONS.md)。

## 原型与后续候选

| 路径 | 当前工作 | 要测的限制 |
|---|---|---|
| Electron/Chromium（当前实验载体） | v0.1.0 已有搜索、五场景阅读、原页、MCP 读取/提案及本地固定字段动作；下一阶段先补状态、权限和生命周期 | 机器链路不证明用户价值；受限动作不证明正式权限模型或广泛站点兼容 |
| CEF 原生宿主（有条件候选） | 只有 Electron 的必需宿主能力被实测阻断时，才做同任务最小切片 | 嵌入 API 不等于完整浏览器；原生 UI、分发、更新和维护待测 |
| Chromium 原生 fork（待 ADR） | 既有固定 stable 构建脚本保留为维护可行性实验 | 上游安全更新、团队规模、自动合并与跨平台回归成本 |
| WebKit 原生壳（冻结的历史对照） | 本仓库 `GridBrowserProbe`：地址栏、标签、真实网页、外部搜索回退；不再扩展 | 历史结果仅供能力比较，不是并行产品路线 |

WebKit 对照样机的搜索会打开 Bing；它没有 Grid 搜索结果页、AI 总结、Agent、同步、资料档管理或安全更新通道。它只提供可运行的 G1 对照负载，不能据此宣称 M1/M2 完成。

## 同负载验收矩阵

先用 Electron 原型执行开发者三项代表任务和 [T0 任务集](./T0_TASKS.md)，比较 A/B 与惯用浏览器；正式内核候选随后按同负载验证。Electron 内存与启动速度不作为原型成功指标。

| 维度 | 观测方法 | 硬性要求 |
|---|---|---|
| 基础浏览 | N01–N05、O01–O03、登录测试账号、常用网站集 | 用户能完成常用任务，无需返回原浏览器 |
| 搜索与原页 | S01–S06、R01–R04 | 真实结果、原页、返回路径可连成闭环 |
| 任务连续性 | C01–C03 | 标签切换不丢目标与页面状态 |
| Agent 控制 | A01–A04；比较同会话页面读取、可信预览、暂停/接管及过期预览拦截能力 | 预览与真实页面绑定；人类接管后旧动作被拒；不需复制登录态 |
| 媒体播放 | V01；实际安装包测试 WebM/VP9、AV1、MP4/H.264/AAC、字幕、全屏、后台播放；记录编解码、硬件和受保护内容状态 | 有声音与画面、拖动和字幕可用；不能播放的格式或站点明确列出，不能用 Video.js 组件掩盖内核缺口 |
| 会议与网页平台 | V02；摄像头/麦克风/共享屏幕、PDF/打印、Passkey、离线网页和文件往返 | 权限可撤销；目标网站可用；每项按系统和安装包记录 |
| 安全 | 官方沙箱/站点隔离配置、权限、恶意页面、升级演练 | 不关闭内核安全机制；可跟进安全修复 |
| 兼容 | 网站、登录、扩展、PDF、视频、输入法、辅助技术 | 记录每个失败，不能用“内核理论上支持”代替测试 |
| 性能 | 同一设备、同一任务测冷启动、P50/P95、完整进程树 RSS、能耗 | 先取得基线，再设置可论证的目标 |
| 维护 | 上游 stable 更新到可发布构建的实际演练 | 有补丁差异、自动构建、回归和紧急发布路径 |

选择结果需要一份写明测试设备、版本、样本量、失败案例、上游更新演练，以及媒体格式/站点、受保护内容、分发许可和基础能力缺口的 ADR。若 Chromium 的安全更新能力无法成立，不因它功能丰富而直接发布；若 WebKit 缺失扩展或真实 Agent 所需的能力，不因其原型轻量而选为正式路线。

- WebKit 样机已在 macOS 实际启动；以公开网页验证了网址直达、网页交互、外部查询导航、后退、新建标签和标签切换。以本地夹具验证了动态表单、iframe、新标签链接与保存下载文件。编译与 `GridCore` 测试通过。

## 下一步顺序

1. 先做用户已选的搜索/场景提取，与惯用浏览器和 A/B 对照；再做连接和接管的探索性真人任务，不预设性能胜率。
2. 按 R2/R3 验证宿主取消、每标签状态、页面/目标失效及动作 unknown；继续限制本地实验权限。
3. 按 R4/R5 验证第二检索、Fetch 回退、辅助进程必要性、实际包兼容和签名升级；保持界面低负担及标准键盘路径。
4. 汇总用户价值、能力阻断、同负载数据与维护证据。只有必要时才比较 CEF/fork；若需 fork，再按[官方构建说明](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/docs/mac_build_instructions.md)演练构建、安全更新及跨平台 CI，完成独立 ADR。
