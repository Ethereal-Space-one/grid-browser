日期：2026-11-04；实施更新：2026-11-05。状态：**第 1–6 步的本机功能实现与自动链路已验证；真人试用由用户进行，内容质量/实际收益待评价。** [第 1 步实测](./SMOKE_PATH_STATE_2026-11-04.md) · [第 2 步恢复边界](./SMOKE_NAVIGATION_2026-11-04.md) · [第 3 步地图实测](./SMOKE_PATH_MAP_2026-11-04.md)。

依据：[主计划 §3.8](../PLAN.md#38-点击递进与链式地图2026-11-04-用户确认待产品实施)、[技术计划 §2.3.1](../TECHNICAL_PLAN.md#231-点击递进与链式地图的接入待实施)、[ADR 0002](./adr/0002-next-stage-architecture.md)。本文件细化已确认的产品方向，服从 PLAN.md；不选择最终内核，不改变 v0.1.0 标签或现有安装包。

## 1. 本阶段要交付的用户体验

用户搜索后，沿来源、阅读、追问、对照和判断逐步前进；随时能在地图中找到旧步骤。返回旧步骤后探索另一条路径，原来的后续仍然存在。正常退出再打开 Grid，可以找回路径、当前节点、选定分支和已保存的任务内容。

默认是一行路径栏，完整地图按需展开。路径记录已访问步骤；模型建议不是已完成节点。首页仍围绕输入与专业、学习、生活、娱乐、灵感五场景；结果先可用，A/B 阅读路线保留。草图中的问答、对照、判断要分别实现，不能用静态页面冒充已接入模型。

范围包含导航、任务内容、本地保存和体验验证；不扩展 Agent 写动作，不引入云同步、推荐画像、完整网页离线镜像或新的内核。路径恢复不等于重放网站操作，也不恢复授权。

以下是实施前核对的工作区基线；当时的测试记录来自[标签记录](./SMOKE_TABS_2026-11-04.md)和[请求记录](./SMOKE_REQUESTS_2026-11-04.md)，规划时未重新运行这些测试；接续第 1 步的复验与改动见本文件开头的实测链接。

| 现状与代码位置 | 对实施的影响 |
|---|---|
| [NavigationStore](../prototypes/electron-m0/src/application/navigation-store.ts) 使用数组与游标；`visit()` 删除游标之后的记录 | 必须改成保留分支的状态模型，不能只在现有历史上画连线 |
| 历史最多 32 项、唯一文本预算 8 MiB，`trim()` 会删除条目 | 路径拓扑与可释放内容缓存分开；不能直接沿用静默删节点策略。新容量上限须测量后明确，不承诺无限保存 |
| [BrowsingSession](../prototypes/electron-m0/src/application/browsing-session.ts) 已有请求取消、版本和每标签状态；搜索/阅读成功后才加入历史 | 提交时就建立有状态的步骤，加载/成功/失败更新同一节点，同时保留上一份可用内容；防止完成时重复建点 |
| NavigationContent 未保存当前 UI 的 `scene`；Search/Reading 自身已有场景上下文 | 节点快照必须明确场景与优化开关，恢复时不能从后来的全局选项推断 |
| [BrowserTab.restorePage()](../prototypes/electron-m0/src/browser/window-registry.ts) 以原生历史索引和 URL 匹配，缺失时加载 URL | 分支截断后索引可能复用；同 URL 的多次访问不能合并为同一文档。失效分支、POST 页面及重新加载必须有明确处理 |
| WindowHost 用固定 `CHROME_HEIGHT` 放置原生网页视图 | 地图展开时需要同步网页可用区域，不能只增加 CSS 高度而让网页遮住地图 |
| [浏览契约](../prototypes/electron-m0/src/contracts/browsing.ts) 仅有 home/results/page/reading，模型接口只有场景提取 | 追问、来源对照、判断笔记及结果短总结没有正式应用实现，单独拆为第 4 步 |
| 现有落盘主要是 key 和 MCP 连接配置；没有恢复仓库，也没有完整私密资料档 | 第 5 步新增受控保存；非持久路径测试不等于完整隐私浏览已经完成 |

## 3. 采用的实施方式与依据

继续当前 Electron/TypeScript、纯业务状态与宿主适配边界；沿用现有 UI tokens，不先换框架。先把有调用方的状态与恢复接口做实，再决定是否需要数据库、独立工作进程或图布局依赖。

| 一手资料（本轮查阅） | 可采用的事实与 Grid 的设计决定 |
|---|---|
| [Electron NavigationHistory](https://www.electronjs.org/docs/latest/api/navigation-history) | 官方接口管理有序历史；Grid 自己管理任务分支，并只在原生条目仍可识别时使用它。分支恢复可行性必须在锁定的 Electron 版本上实测 |
| [Electron NavigationEntry](https://www.electronjs.org/docs/latest/api/structures/navigation-entry)及已安装 Electron 45 类型 | `pageState` 可包含滚动和表单值；因此本阶段不将整份原生历史/pageState 放入任务文件或 IPC |
| [Electron 资源管理](https://www.electronjs.org/docs/latest/api/base-window#resource-management) | 子视图的 webContents 需要显式释放；保留路径不等于为每个节点常驻一个网页实例 |
| [WAI-ARIA Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) | 地图展开入口使用原生按钮、展开状态与键盘操作；路径节点先用嵌套列表和按钮表达，不只依赖图形连线或颜色 |
| [Node 文件写入](https://nodejs.org/api/fs.html#fspromiseswritefilefile-data-options) | 同文件并发写入需要协调，取消也不意味着没有写入；采用单写者、版本和明确提交点，持久性仍须故障注入验证 |

上述资料支持接口与风险判断。树状路径、保存结构、节奏和视觉层级是 Grid 的设计选择，不是资料替项目证明的最佳结果；Apple 风格只作为克制色彩、排版和反馈的方向，沿用[设计实践记录](./DESIGN_PRACTICES_2026-11-04.md)，不声称复制官方色值。

## 4. 六步交付与依赖

| 步骤 | 用户可验收的变化 | 主要实现位置 | 出口与状态 |
|---|---|---|---|
| 1. 分支状态 | 后退后探索新来源，旧后续仍可找回；节点拥有各自场景和草稿 | contracts、NavigationStore、BrowsingSession | 本地状态及真实 UI/IPC 回归通过；该步交付底层，节点选择界面由第 3 步接入，见[实测](./SMOKE_PATH_STATE_2026-11-04.md) |
| 2. 宿主导航 | 地图跳转、前进后退与真实网页保持一致，失效页面有明确恢复入口 | BrowserTab、WindowHost、main/preload | 已本地验证：39 项本地检查、16 组导航与既有回归；地图可视入口仍属第 3 步 |
| 3. 路径栏与地图 | 在真实搜索/阅读流程中点节点、切分支；默认不挤占内容 | renderer、tokens、宿主布局接口 | 10 组地图检查、39 项本地检查及既有回归通过；完整无障碍/真人体验另验 |
| 4. 逐步展开的理解流程 | 短总结、问这页、来源对照、我的判断按点击分别出现 | Model 用例/adapter、contracts、renderer | 4A、4B、4C 已本地验证；最新 62 项本地、9 组判断 UI/IPC，运行期间保存 |
| 5. 本地保存与恢复 | 退出重开仍可继续；可查看保存状态、删除路径 | storage、应用生命周期、恢复界面 | 已完成本机实现：74 项本地检查、4 个独立 Electron 进程恢复/删除/故障保护，正文全文不落盘 |
| 6. 品味与完整任务 | 用户看得懂位置、分支与保存状态，能完整完成搜索到判断 | UI、端到端脚本、真人任务记录 | 视觉/无障碍与真人结果分别报告；待实施 |

顺序为 1 → 2 → 3 → 4 → 5 → 6。第 1 步就定义可序列化边界，第 3 步就执行视觉与键盘检查，第 4 步提前定义内容版本；第 5 步才启用落盘。第 6 步是整体验证与精修，不将体验质量拖到最后补救。

### 第 1 步：分支状态与不可变节点上下文

交付：在现有 NavigationStore 内渐进替换线性游标，实现节点、父子关系、当前节点、选定子节点和快照查询；先服务已有搜索/原页/阅读/提取，不为未实现页面生成假节点。

- 区分稳定的 pathId/nodeId 与本次运行的窗口、ownerId、文档身份；稳定 ID 不成为权限凭据。每标签有明确路径归属，跨标签来源对照以后通过显式引用建立关联，不静默合并其他标签。
- `visit` 新增子节点，`replace` 只更新本步，`back/forward/jump` 只移动；地图跳转更新祖先的选定后续。父子无环、选定后续为直接子节点；同 URL 多次访问保留独立身份。
- 节点快照固定查询、五场景、优化开关、来源/内容版本与展示状态。搜索/Fetch 提交即建立 pending 节点；成功或失败更新该步，取消后保留可判读状态，不重复加入成功节点。等待时仍可查看上一份可用内容，并明确其属于上一步。
- 请求租约绑定 owner、nodeId、runId 和版本；离开节点取消未完成请求，返回也不复活旧请求。相同节点的新请求不接受前一代响应。
- 分离小型路径结构与内容记录引用。内容缓存可在预算内释放，但节点和笔记不能被旧 `trim()` 默默删掉；元数据达到上限时明确提示并保留现有路径，普通浏览仍可继续。

验收：A → B → C，返回 B 打开 D 后 C 仍在；选择 C 后前进方向改变；跳转不增节点；各节点场景与草稿独立；旧请求晚到不覆盖当前或已取消节点；内容释放后路径仍可导航且明确显示缺失。

回退：这一份改动不写磁盘；未通过前保留旧应用可运行的工作区快照。若退回线性导航，只用于未发布实验，不能静默转换并丢弃用户分支。

### 第 2 步：统一真实网页与产品导航

交付：通过 Browser Host 统一跳转命令、按钮/快捷键和地图入口，复用现有 sender、owner 与 schema 校验；不在 renderer 另建历史。

- 先在隔离夹具验证：网页 A → B → C，回到 B 打开 D，再恢复 C；同时包含同 URL 不同状态、SPA、锚点、重定向、视图崩溃和 POST 回执页。用服务器请求计数证明恢复没有重复提交。
- 原生索引只在对应视图和当前历史代次中有效；新分支截断或视图销毁后使受影响映射失效。不能仅凭“索引相同且 URL 相同”认定旧页面仍然存在。
- 存活实例可恢复时复用；需要重新加载或无法判定是否涉及提交时，先显示保存上下文和原因，再由用户选择打开原页。Grid 不主动重新发送 POST、执行 Agent 或重放其他写操作。重新打开网站仍会运行站点自身脚本，不承诺冻结动态网页。
- 主框架新文档形成步骤；同一次跳转的重定向不膨胀节点，锚点只更新位置，实际切换内容的 SPA 路由纳入路径。恢复过程产生的导航事件更新目标节点，不另建重复节点。
- 离开所见文档继续撤销旧授权和动作预览；跨标签旧命令拒绝。为恢复新建的网页视图也必须按现有策略管理权限及资源。

验收：地图、地址栏、菜单快捷键观察到同一当前节点；重复 URL 不串文档；返回旧分支不误开后来占据相同索引的页面；POST 计数不增加；授权不恢复；关标签取消其请求并释放视图。

回退：无法可靠恢复的网页保留节点和任务内容，降级为明确的“需要重新打开”入口，不自动复制页面状态或创建常驻影子浏览器。若实验表明必须改变已确认的恢复范围，带具体复现和可选方案通知用户判断。

### 第 3 步：在真实应用接入路径栏和地图

交付：将已确认的草图转为正式 renderer 组件，使用宿主节点快照；先支持已有页面类型。

- 默认一行紧凑路径，展开呈现父子关系、当前节点与选定后续；其他分支可点，文字名称与来源帮助区分重复步骤。较深路径按需展开/滚动，不能为了适配宽度删除节点。
- 节点使用语义列表与可聚焦按钮；连线属于辅助图形。展开按钮提供 aria-expanded/aria-controls，当前位置有可读状态；收起后焦点回到入口，跳转后内容标题或原有合理焦点可达。
- 宿主接收可信 UI 的有界布局更新并重新计算 WebContentsView 区域；处理窗口缩放、系统缩放、Agent 面板与地图同时存在，不能用 CSS z-index 假定可以覆盖原生子视图。
- 沿用浅深色、中性色和场景强调色；当前路径与分支不用颜色单独区分。减少动态效果下立即切换，动效不影响点击命中和导航结果。

验收：真实结果 → 阅读 → 原页可见节点；点击 C 与 D 来回切换不重请求；展开地图不遮住网页/可信控制，收起恢复阅读位置。覆盖实际最小窗口和 320/375 等布局检查；窄幅截图不等于应用已支持对应原生窗口尺寸。

回退：保留宿主分支状态，暂以可访问的层级列表替代连线地图；普通地址栏、前进后退、搜索和阅读仍可用。不能退回为只有图片、不可点击的地图。

### 第 4 步：把草图中的理解流程逐项落地

每一小步独立交付，不把三类页面和全部按钮堆在结果页，也不将已有“场景提取”改名当成完整问答。

| 小步 | 实现内容 | 独立验收 |
|---|---|---|
| 4A：短总结与问这页 | 结果可用后按需生成短总结，失败仍保留结果；点击“问这页”进入独立问答状态，只使用本次明确页面/正文版本与问题。新增有边界的 Model 接口，复用取消、超时、响应上限，保留原文与依据 | 提交问题创建节点；流式或最终回答只更新本步；返回不再调用模型；草稿恢复；摘要依据与已读原文分开标注，无法取得内容不编造答案 |
| 4B：来源对照 | 用户主动选择至少两份来源后，显示临时入口；点击进入独立对照页。固定选定来源 ID、内容版本、场景和查询，不读取未选标签；缺失来源可补取或打开原页 | 未请求比较时不占主页面；来源冲突、不完整与抓取失败分别说明；回原文后能返回同份对照；引用可定位且不冒充已核实结论 |
| 4C：我的判断 | 用户从问答/对照主动记录判断，独立呈现自己的文字、引用和待核事项；编辑只更新草稿，保存形成有版本的判断节点 | 切换分支保留草稿；用户文字与模型建议可区分；引用指向正确来源/版本；此时仅完成运行期间保存，持久保存待第 5 步 |

正文与模型的输入范围对用户可检查。原页 A 中的登录/动态内容受现有权限和读取能力约束，不因“问这页”获得跨标签或通用 Agent 权限。模型不能作答时，原页与阅读仍可用。需要新 API 能力时先核对官方参数和当前 adapter，不假设 Fetch 接受 prompt。

### 第 5 步：本地保存、重启恢复与删除

先采用版本化文件与明确提交点；路径元数据、任务内容、正文缓存、凭据和动作回执分开。具体文件数量和额度在本步用代表路径验证，不先引入图数据库或同步服务。

| 小步 | 交付与要求 | 验收 |
|---|---|---|
| 5A：存储契约与写入 | 白名单序列化路径/当前节点/选定分支、查询/场景、结果必要字段、回答/提问草稿/笔记及来源时间；排除原始正文、原生 pageState、网页字段、Cookie、凭据和完整内部提示词。schema/大小/引用均校验，单写者合并频繁更新 | 用包含合成秘密的状态检查序列化结果；运行时对象、控制器与授权不会进入文件；超限和写失败可见，不能假称已保存 |
| 5B：提交与恢复 | 先写齐一代内容，再以原子替换方式提交对应清单；确认完成后才显示“已保存”。启动验证版本与引用，重建新的 runtime owner/documentId；正常退出等待有界写入，异常恢复只承诺最近已提交状态 | 新进程从同一临时资料目录恢复路径和当前分支，不是同进程刷新；覆盖写入各中断点、缺失内容、损坏/未知版本和只读目录；不自动请求模型、加载可能重提交的页面或执行动作 |
| 5C：管理与非持久策略 | 查看最近路径并恢复；删除整条路径时处理相关专属内容、旧版本和临时文件，避免备份自动复活。非持久路径不参与写入；未具备独立私密资料档前，不将其宣传为完整隐私浏览 | 删除后退出重开仍不存在；未完成的旧写入不能写回已删除路径；共享来源不被误删；非持久数据不混入普通窗口恢复文件；损坏记录隔离而非覆盖唯一原件 |

大正文不落盘意味着重启后某些阅读内容不可直接恢复；显示其来源、时间与已保存回答，提供显式重新获取/打开原页。释放可重新获取的缓存与删除用户笔记是不同操作；容量达到上限须提示，不能静默裁掉分支或判断。

回退：恢复仓库故障时仍可启动普通浏览，并显示哪些内容未能恢复；保留可诊断的最小元数据，不上传用户内容。新格式升级前保留版本可判读性；未知新版本不交给旧程序覆盖。文件替换不被表述为跨平台断电零丢失保证。

### 第 6 步：UI 品味、完整链路与真人验证

视觉精修围绕当前内容、当前位置、下一次点击和保存状态，复核字号/行长/间距、浅深色层次、五场景强调色、分支可读性和过渡；保持结果与原页易到达，不增加常驻控制台。实际截图必须覆盖搜索后的阅读、问答、分支、对照、判断和恢复失败，不只展示首页。

固定自动验收任务：

1. 用学习场景提交查询，结果先显示，进入 A 并阅读、追问，留下提问草稿。
2. 回到旧节点选择 B，确认 A 的追问及草稿仍在；切回 A，再用前进回到它的后续。
3. 明确选 A/B 发起对照，检查来源与内容版本，保存自己的判断。
4. 正常退出并启动新进程，恢复当前判断、地图分支和任务内容；缺失正文明确回退。
5. 重复异常中断、正文/模型失败、保存失败和删除流程；整个过程的 Search/Fetch/Model 调用次数与写入计数可核对。

自动回归先用合成提供者与本地页面，记录取消、节点/版本、调用次数、保存代次和结果，不记录个人密钥或正文。按改动影响运行既有 `npm test`、tabs/requests/scenes/MCP/actions/visual 回归；新增路径、问答及重启用例的脚本名称在实现时登记，不把未创建命令写成可运行入口。

真人任务使用用户已经选择的“搜索并按场景提取正文”，再加入分支找回与重启继续；与惯用浏览器同题记录完成情况、重复搜索、等待、位置/分支理解与主观负担。不用 API 时长或内部评分代替体验收益。真实接口验证与人工内容质量评价分别记录；不能以模型返回非空代替依据准确。

出口：自动流程通过且已保存的数据可在新进程恢复，才称“链式地图功能实现”；真人理解与收益未测时仍明确标为待验证。本机验证不代表跨平台安装、正式签名、更新或日用浏览器门槛通过。

## 5. 每步的交付纪律与卡点处理

每份改动交付可运行路径、对应测试与实测记录，写明本次用户可见变化、未实现项和回退方式。不预设工期或完成百分比；代码、脚本、真实接口、真人体验和发布包分别报告。

第 1–3 步可以先形成“现有页面的运行期间分支导航”，第 4 步逐项增加内容类型，第 5 步已完成本机的新进程恢复检查；未通过的跨平台与真人范围不计入保存实现。旧测试中“新访问丢弃前向历史”的断言须按新产品要求替换，同时保留隔离、位置、资源预算和授权失效的检查，不仅调整计数使测试变绿。

目前没有需要用户裁决的实际阻断。实现中只有在必须改变已确认体验、引入新服务/数据外发或重选宿主时，才带复现、影响及可选方案通知用户；常规实现与修复继续推进。主要待实验点为原生分支失效后的恢复、地图与网页视图布局、长路径容量及保存一致性。
