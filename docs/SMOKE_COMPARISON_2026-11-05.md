# 4B 来源对照：实现与本地验收

日期：2026-11-05。依据：[主计划 §3.8](../PLAN.md#38-点击递进与链式地图2026-11-04-用户确认待产品实施)、[六步实施表](./PATH_MAP_IMPLEMENTATION_2026-11-04.md)。沿用 Electron/TypeScript 与既有界面 tokens，没有引入新 UI、模型 SDK 或图布局依赖。本轮未推送，v0.1.0 标签与安装包未改变。

## 用户得到的流程

1. 在当前标签的结果、已取得的 Fetch 正文或带正文版本的问答页主动选择来源。选择不联网、不建路径节点；未选择时不显示来源栏。选择一份时只提示再选一份，两份后才出现“对照这两份”。一次限定两份，不自动替换第三份，也不将同一地址的锚点当不同来源。
2. 点击后进入独立对照页，提交即建一个路径节点；取得正文及模型完成只更新本步。固定来源 ID、选择位置、查询、场景和正文版本，不遍历或读取其他标签。已选的正文版本直接使用；从结果选择但尚无正文的来源才调用公开 Fetch。
3. 展示“一致”“说法有分歧”“适用范围不同”“资料不足”四种关系，全部标为待核对的 AI 观察。缺失信息不等于反对；抓取失败不作为来源冲突。没有最终排名或由模型替用户作出的判断。
4. 左右依据分别定位到对应版本的逐字原句，可回到刚才的对照项。两份正文各有时间、截取提示、展开查看、原页及返回选择位置入口；从原页或原先阅读位置能返回同份缓存对照，不重复请求。
5. 一份抓取失败时保留另一份已取得的版本，不调用模型。显式重试只补取缺失来源；模型失败保留两份正文，可按相同版本重试。重试形成新步骤，原失败或取消步骤仍在。
6. 旧正文/对照因缓存预算释放后，路径仍保存两份来源地址、标识和原版时间。返回只提示缺失，不自动联网；点击“重新获取两份正文并对照”才补取新版本并建立新步骤，不把旧结论或当前篮子冒充原来的资料。

临时选择栏属于当前标签，最多保留两份选定文本片段；它不属于导航树或跨重启恢复文件。切标签显示该标签自己的选择，返回旧节点不会倒退或自动改写当前选择；每份已提交对照则使用自己固定的来源。

## 技术与数据边界

新增 [Comparison 契约](../prototypes/electron-m0/src/contracts/comparison.ts)、[模型适配](../prototypes/electron-m0/src/providers/comparison.ts)和独立 DOM 对照组件；复用 BrowsingSession、NavigationStore、可信 UI sender 和主进程状态。接口校验 owner、entry、选择句柄/结果索引与对照记录 ID，不接收 UI 提供的任意正文或来源 URL。

每份来源最多发送前 16000 个 Unicode 字符；未抓取来源最多同时发起两个 Fetch，每个沿用 15 秒超时，之后模型沿用 20 秒超时、2 MiB 响应上限与取消链。最坏等待由 Fetch 阶段与模型阶段相加，不无限重试。已取得的一份可先显示；停止会中止所有未完成请求。晚返回、切场景、导航、界面重载、标签关闭或销毁不能复活旧请求。

模型使用既有 `deepseek-flash` JSON 接口，关闭 thinking、不提供工具，最多四项对照。应用校验完整结束、结构、长度和逐字依据归属；左边不能使用右边独有的引文。声明未说明的一侧不接受引文，并由应用固定显示缺失提示；至少一边缺失时只接受“资料不足”关系。模型不提供可执行动作或任意链接。

官方 [JSON Output 说明](https://api-docs.deepseek.com/guides/json_mode/)用于核对结构化请求和空白/截断输出的处理。结构通过、引文存在和关系标签都不能证明语义正确，仍须人工核对。原页入口仅按用户操作打开；对照服务不读取登录资料档、Cookie、表单字段或未选标签。

对照正文/回答沿用 8 MiB 内容缓存；来源元信息与正文分离，释放不删节点或来源句柄。仅本次运行保留，没有任务落盘或旧授权恢复。选择栏改变原生网页区域时，由既有带票据的布局同步处理；布局变化不撤销所见文档授权，导航仍撤权。

## 边做边检查

- 修改前保存上一阶段源码，保留所有已有未提交工作；先检查主计划、4A 契约和设计 tokens。
- 先完成受限选择与模型/缓存契约，再接界面。最初一个负面单元检查太晚接住预期拒绝，修正测试等待顺序后 55 项本地检查通过。
- 窗口测试发现合成模型把左右顺序写死，交换选源时应用正确拒绝串边引文；修正测试夹具，并要求正常分支必须取得有效对照。另修正测试表达式错误，不放宽产品校验。
- 实际截图后压缩重复的来源说明，把重试放入页面操作区；补上标题的 token 焦点、依据与对照项的双向返回。宽屏并排，窄屏逐项呈现 A/B；动作不换成两行按钮。
- 整体回归后复查缓存释放，补齐独立来源元信息和显式新版本恢复；再做本地与受影响流程复验。

## 仍然存在的边界

本轮证明了本地实现与合成链路，没有真实模型内容质量、真人收益或 Fetch 广泛站点覆盖结论。公开文本可能与原页不同或过时，只看前缀可能漏掉关键内容；分歧标签不能判断谁对谁错。

一次只对照当前标签主动选择的两份来源，暂不跨标签收集，不支持登录态/动态页面全文、三份以上同时对照或交互式重排。新版本补取是显式新步骤，不恢复原来的冻结网页。判断笔记、跨重启保存、删除/隐私路径、正式安全及分发仍待后续阶段；没有新的安装包或远端 CI 通过结论。

下一步为 4C“我的判断”：由用户记录自己的结论、引用和待核事项，区分用户文字与模型建议，再进入第 5 步本地保存。
