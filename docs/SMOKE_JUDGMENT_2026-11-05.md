# 4C 我的判断：实现与本地验收

日期：2026-11-05。依据：[主计划 §3.8](../PLAN.md#38-点击递进与链式地图2026-11-04-用户确认待产品实施)、[六步实施表](./PATH_MAP_IMPLEMENTATION_2026-11-04.md)。沿用 Electron/TypeScript、纯应用状态、可信 UI/IPC 与现有 Grid 设计 tokens。本轮未推送、未生成新包，v0.1.0 标签不变。

## 用户得到的流程

1. 完成问答或两份来源对照后，点击“记录我的判断”进入独立页面。自己的结论与待核事项从空白开始，不复制模型文字；AI 建议在单独折叠的参考区，带“未核对”标签。
2. 编辑只更新当前草稿，不增加路径节点。草稿的结论、待核事项和引用选择保留在所属标签与分支；快速输入后立即切换标签、返回旧分支或重载 UI 均能恢复本次运行中的内容。
3. 原文引文按需展开、逐条选择；只可选这版问答/对照中已逐字匹配的引文。每条保留来源地址、正文版本标识、取得时间、截取标记和原句。保存的版本只展示实际选择的引文，重新编辑仍可选择原版候选。返回参考位置不重新调用服务。
4. “保存为新版本”新增只读节点；“修改为新草稿”建立新步骤，后续保存再产生新版本。同一判断谱系的版本号递增，从旧版本另起的修改也不覆盖原版本；旧草稿仍可回看、继续编辑。
5. 保存必须匹配当前草稿和修订号。更新被拒时，文字留在输入框中，提示重试且禁止虚假的保存成功。路径或内存容量不足时拒绝新增版本，保留现有草稿。长引文按需展开，保存按钮置于页首，不要求先读完全部引文。

**这些记录只保留在本次运行中，退出后暂不保存。** 完整退出、重启与删除属于第 5 步；不能把 UI 重载恢复写成跨重启保存。

## 技术与数据边界

新增 [Judgment 契约](../prototypes/electron-m0/src/contracts/judgment.ts)、独立判断 UI 与检查脚本；复用 BrowsingSession 和 NavigationStore。接口仅接受 owner/entry/draftId、修订号、个人文字和引用句柄，拒绝 UI 提供的任意引用地址、重复/外来引文、过长文字和旧请求。草稿修订号只能递增，保存必须精确匹配；每份载荷使用新缓存 ID，旧版本不会因缓存 ID 重用而被修改。

结论最多 4000 字符、待核事项最多 2000 字符；候选引文最多 24 条、每条最多 1000 字符，模型参考最多 12000 字符。当前问答/对照适配器自身的输出上限更小。引文元信息从 Host 的原始来源派生，模型自报标题/地址不进入个人引用记录；逐字命中仍不代表结论或适用范围正确。

个人判断属于独立文本载荷，计入既有 **8 MiB** 预算，优先于可重新取得的提供者正文保留。新增或更新前检查个人载荷所需空间；32 个路径记录达到上限时不假装产生可回看的新判断版本。路径元信息仅保留版本/来源位置等句柄，不含个人文字、引文或模型输出。普通内容缓存释放后，保留的判断仍能显示原句与对应正文版本；极小自定义预算或缺失载荷只提示无法自动重建，不请求模型补写个人结论。

判断这一步没有新增网络请求或任务文件写入。个人结论与待核事项不发送给模型，也不变成检索/问答的隐含上下文。现有 MCP 授权与固定填写动作的范围不变。
