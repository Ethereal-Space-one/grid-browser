# MCP 只读桥接实测

日期：2026-11-02。本机 macOS、Electron 45.2.1、官方 MCP 服务端及客户端 SDK 2.4.0。使用真实 Electron 页面、真实 stdio 子进程和本机管道；没有调用模型或 Search/Fetch，也不需要 API key。

2026-11-03 阶段收尾复验：八项本地检查及下表完整端到端流程再次通过，进程退出码为 0。记录日期保留首次实测日期。

同日还以既有 key 复跑真实 Search → Fetch → 原页 → 返回结果的五项流程，全部通过，退出码为 0，未发现本次桥接接入破坏原有搜索链路。

`npm run test:e2e:mcp` 在临时浏览器资料档中运行本机测试站，通过 HttpOnly 测试 Cookie 打开需要该测试会话的页面。随后从产品的“复制 MCP 配置”取得入口，由官方 SDK 客户端执行初始化、工具发现和调用，并通过 Grid 界面授予及撤销权限。

| 检查 | 结果 |
|---|---|
| stdio 初始化与工具发现 | 仅提供连接状态和页面只读摘要两个工具 |
| 授权前读取 | 拒绝 |
| 同一浏览会话读取 | 读取到当前测试登录态页面的标记文字 |
| 输入、密码与可编辑内容过滤 | 测试字段值未出现在返回摘要中 |
| JSON 读取回执 | 包含拒绝与成功事件及摘要哈希，不含测试正文或字段值 |
| 撤销后读取 | 拒绝 |
| 同站导航后读取 | 旧授权失效，拒绝 |
| 客户端断开 | Grid 中的连接移除 |

另有本地契约测试验证错误本机令牌、读取过程中撤销、文档身份变化和输出长度边界。修正后的流程退出码为 0。首次运行发现 Electron 45 剪贴板 API 返回 Promise，已补上等待并复跑通过；也修正了测试失败仍可能显示进程退出码 0 的问题。

自动报告与本机 JSON 回执在原型的 `.local/` 中，不进入仓库。脚本记录的客户端握手耗时是自动化观测，不是首次用户接入时间或性能优势。真实宿主的配置步骤数、首次成功读取耗时、Windows/Linux 实际安装与系统权限、iframe、完整恶意网页测试和最终内核安全模型仍待验证。
