# 链式地图第 2 步：宿主导航与网页恢复

日期：2026-11-04。范围：[六步计划第 2 步](./PATH_MAP_IMPLEMENTATION_2026-11-04.md#第-2-步统一真实网页与产品导航)。状态：**受控节点跳转、原生访问失效与提交恢复边界已本机验证；路径栏/地图界面与跨重启保存未完成。**

## 用户可见变化

Grid 的后退、前进、刷新及菜单快捷键由同一宿主管理，结果、阅读和真实网页共用当前任务节点。已准备可信 UI 的任意节点跳转接口，地图中的选择入口将在第 3 步接入；当前没有把全部节点铺在页面上。

旧网页访问被新分支覆盖、进程崩溃或视图关闭后，保留步骤并显示原因。此时隐藏不属于该步骤的存活网页，允许用户点击“重新打开地址（不重发表单）”发起新的 GET，内容可能变化。返回或刷新不会自动重发 POST；即使提交后以 303 转到 GET 页面，仍保留提交边界。重新打开不恢复 MCP 读取授权、动作预览或 Agent 执行。

恢复提示沿用现有浅深色与场景 tokens，显示地址、原因和下一步。焦点进入可读标题，Tab 可到重新打开按钮，Enter 可执行；最小 720×480 原生窗口中按钮可见。标签标题使用所选步骤的地址，避免显示上一页的标题。

## 实现与一手依据

- `NativeVisits` 为本次运行中的每次访问生成独立 ID，记录视图内的索引、URL、节点和请求方法类别；相同 URL 或索引不是访问身份。新分支截断、同位置替换及历史形状变化使受影响绑定失效。账本最多 256 项，只存小型元数据，不读取或复制原生 `pageState`、表单值、Cookie 或上传体；它不是权限凭据或磁盘恢复格式。
- Browser Host 对跳转验证可信调用窗口、当前标签、发出命令时的节点及目标归属；重新打开还绑定当前恢复提示的一次性 ID。旧提示、跨标签、外来节点和过期命令在加载前拒绝。
- 明确的宿主恢复只使用仍有效的原生访问；可确认的 GET/HEAD 历史允许浏览器导航，POST/未知方法不自动恢复或刷新。没有有效访问时不自动调用 `loadURL`。仅用户明确重新打开才发起 GET；站点自身脚本仍可能运行，这不是冻结网页或阻止一切站点副作用的保证。
- profile 只注册一份主框架请求分派器，按 Electron 给出的 webContents ID 找到真实标签。恢复/刷新期间阻止非 GET/HEAD 的主框架请求，方法分类跨重定向保留。子框架的导航与重定向不改主任务节点。
- 主框架新文档和 SPA 新访问形成步骤；重定向更新同一步，锚点只更新位置。不同 URL 的 `replaceState` 保留旧任务节点，但旧原生位置明确失效。Chromium 联合历史还包含 iframe，子框架变化只重新绑定当前主文档的位置，不新增主任务步骤。返回已知旧节点不再创建副本；离开会取消请求并撤销授权，迟到的加载或旧视图事件不能改写新目标。后台页导航只撤销自己的预览，不误撤销当前页授权。
- 加载失败/超时、渲染崩溃、WebContents 销毁均进入明确恢复状态；加载等待有 15 秒上限，不自动循环重试。每个标签仍只有一份按需创建的网页视图，没有为每个节点建立常驻浏览器副本。

本轮重新查阅 [Electron NavigationHistory](https://www.electronjs.org/docs/latest/api/navigation-history) 和 [WebRequest](https://www.electronjs.org/docs/latest/api/web-request)，并以锁定的 Electron 45.2.1 类型核对导航事件。官方历史恢复为尽力恢复，原生状态可能含表单值，因此没有序列化整份历史；WebRequest 同一事件只保留最后一份监听器，因此使用 profile 级单一分派。具体行为仍以以下真实窗口实验为证据，文档本身不证明 Grid 已安全或兼容全部站点。

新增导航实验逐项覆盖：

1. 结果 → 正文 → 原页 → 原页点击，再以受控节点跳转返回，和前进/后退使用同一当前节点。
2. A → B → C，回 B 打开与 C 相同 URL 的 D；C 保留但显示失效，不能误显示 D，也不自动请求或沿用读取授权。
3. 明确重新打开 C 后仍使用 C 的任务节点，得到新 GET 内容，需要重新授权。
4. POST 回执页返回/前进/刷新不重发；过期恢复提示不能打开页面。
5. 恢复页实际最小窗口、浅深色、标题焦点及 Tab/Enter 操作。
6. POST→303→GET 后仍阻止自动恢复提交步骤。
7. 同 URL 的两次 SPA `pushState` 分别保存，受控跳转恢复其对应页面状态；锚点不新增任务节点。
8. SPA 返回后再 `pushState` 保留旧分支，新状态不继承旧身份；页面发起的后退选择已有节点。
9. SPA `replaceState` 切换路由新增任务步骤，被替换的旧位置显示失效，不自动抓取。
10. 一次重定向只形成一个任务节点；外来、过期和另一标签的跳转被拒。
11. 清空原生历史后不能凭相同 URL 猜测旧访问，也不自动重新请求。
12. 加载中切回结果节点，旧加载结束不能覆盖结果或重新附加网页。
13. 有意使隔离网页进程崩溃；路径保留，明确重新打开后可继续，授权不复活。
14. 关闭网页 WebContents 后停在恢复页，明确重新打开才创建新实例。
15. iframe 跳转和重定向不改变主框架的节点、URL 或节点数量。
16. 后台标签发起导航不替换当前步骤或撤销当前文档的授权；实际 MCP 读取仍成功。

## 实验发现与修正

实施前已实际复现“同 URL 且索引复用后，选旧 C 却显示新 D”。新增访问账本与显式失效入口后，原用例及 SPA 分支变体均通过。

首次真实导航实验出现 Electron 进程 SIGTRAP。调整了导航回调内停止加载及拆卸视图的时序：页面自身导航保持原视图，只对宿主明确恢复显示占位。原触发用例复验通过；这不等于确认 Electron 内部全部成因或证明应用没有崩溃。后续又修复了授权撤销同步发布在访问尚未提交时清空绑定、已销毁视图的 WebContents 为 undefined 时无法重新创建，以及子框架联合历史与后台导航干扰当前页授权的问题，并用真实窗口用例覆盖。

## 剩余边界与下一步

- 可点击地图与分支选择界面尚未接入，第 3 步才处理原生网页可用区域、地图展开/收起与焦点。第 4 步的问答/对照/判断和第 5 步的本地保存/重启/删除仍未实施。
- 只承诺 Grid 自身按钮、菜单和受控节点命令的确定目标。网页脚本自行前进时，当前使用的事件不含唯一原生访问 ID；前向槽既可能是旧访问，也可能被新分支复用，因此保守地作为新访问处理，保留旧任务分支。不能以放宽 URL/索引匹配来合并；后续若需要更精确地合并站点自己的前进操作，须另加可信的原生标识实验。
- 跳回有效 GET 原生历史仍可能由浏览器重新取页，站点状态和阅读位置只尽力恢复；搜索、Fetch 和模型不会因返回而自动重新调用。失效的 SPA 状态没有通用重建保证，重新 GET 不能冒充原状态重现。
- 32 个记录节点及 8 MiB 内容预算仍按第 1 步限制；访问绑定另有 256 项上限，淘汰后保留路径并提供恢复入口。容量不是无限历史承诺。
- macOS CI 已加入导航脚本；本轮未推送或取得远端 CI 结果。现有 v0.1.0 标签、安装包和依赖版本未变，没有跨平台安装、真实内容质量、真人收益或正式安全结论。
