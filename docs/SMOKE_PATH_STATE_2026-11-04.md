# 链式地图第 1 步：分支状态与请求归属

日期：2026-11-04。范围：[六步计划第 1 步](./PATH_MAP_IMPLEMENTATION_2026-11-04.md#第-1-步分支状态与不可变节点上下文)。状态：**已完成本机状态与既有界面回归；地图界面、任意节点 UI 跳转、原生网页失效分支恢复及磁盘保存均未完成。**

## 本轮实现

- `NavigationStore` 从线性数组改为有界树：独立 pathId/nodeId、父子关系、当前节点与选定后续。返回后新增访问保留旧后续；纯用例 `jump()` 更新祖先的前进方向，同 URL 多次访问不自动合并。界面状态包含当前标签的路径摘要，未新增 UI 跳转 IPC。
- 节点保存自己的场景、查询上下文、展示草稿、优化选择和阅读位置；提交时另行固定原问题/实际查询/场景/优化快照及目标，取消后再改场景也不会改写原请求。快照及内容记录不可变；从另一标签或路径传来的节点 ID 不能用于跳转。
- Search/Fetch 在提交时形成 pending 步骤，完成或失败更新同一节点；模型场景提取仍更新当前阅读节点。等待时继续展示上一份可用内容并标明状态。请求绑定运行 ID、owner 与节点，离开会取消；即便返回同一节点，旧响应也不能恢复执行或补写。
- 路径与内容缓存分离。预算释放旧结果/正文/提取时保留节点、来源关联、场景和位置；缺失内容明确提示，禁用不可用的提取，允许打开真实原页；不因返回自动再请求服务。
- 保留原型的 **32 个记录节点**与 **8 MiB 唯一内容记录预算**。超过节点上限时保留既有分支，明确提示后续仅暂存当前步骤，并最多维持一个未记录续页；继续浏览不报错，后退回最近记录节点。这不是无限历史或日用容量承诺。内容预算按序列化记录的 UTF-8 字节计，不是进程内存上限。
- 修复取消后按钮隐藏造成的键盘焦点丢失；等待期间新输入的草稿在结果完成后仍保留，原请求的查询/场景上下文不被草稿改写。
