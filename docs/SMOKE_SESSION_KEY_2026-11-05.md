# API key 仅本次使用：取消钥匙串密码提示

2026-11-05。用户反馈启动时的系统密码提示会带来风险顾虑。本轮修改密钥配置流程，保留已确认的同窗阅读、场景和链式地图交互。

## 行为

- 启动不再读取 `provider-key.bin`，配置不再调用 Electron safeStorage。Grid 的 API key 配置不访问系统钥匙串、不要求电脑登录密码。
- 首页「搜索服务设置」明确只输入 DeepSeek API key，按钮改为「本次启用」。输入后立即清空字段，主进程仅在本次运行中使用，不写入配置、任务文件或日志，不返回给页面状态或远程网页。UI 的「已配置」不等于真实服务验证通过。
- 完全退出 Grid 后手动配置失效；macOS 仅关闭窗口仍保留进程，重新开窗口不要求重复输入。已有 `DEEPSEEK_API_KEY` / `DeepSeek_ApiKeyN` 环境变量保持兼容，前者优先。
- 原有密文文件保持原样，不读取、不覆盖；本次没有访问或删除用户真实钥匙串。没有用明文文件替代加密存储。
- 未配置 API key 仍可直接打开网址。本轮不提供跨启动自动记忆 key；需要该能力时另行设计，不隐式引入系统密码弹窗。

## 验证

- `npm test`：77 项通过。
- `npm run test:e2e:key-storage`：六次独立 Electron 启动通过，覆盖新资料档配置/重开、已有旧密文配置/重开、两个环境变量同时存在及兼容变量单独存在。测试将全部 safeStorage 方法替换为计数并失败的守卫，旧密文读取也设守卫；启动、配置、搜索均为零调用。
- 真实 UI 表单提交、字段清空、无效替换保留已有 key、新窗口和界面重载继续使用本次 key、未配置时打开本机网页、网页无 Grid 桥接、提供者请求使用当前 key 均通过。请求使用合成响应，不消耗真实 API，也不代表真实 key 或内容质量已验证。
- 六次退出后扫描各自临时资料档，未发现合成 key。新资料档未生成密钥文件，旧测试密文逐字节不变。重启后手动 key 不恢复。
