# 第 5 步：本地保存、重启恢复与删除

日期：2026-11-05。依据：[主计划 §3.8](../PLAN.md#38-点击递进与链式地图2026-11-04-用户确认待产品实施)、[六步实施表](./PATH_MAP_IMPLEMENTATION_2026-11-04.md)。继续使用 Electron/TypeScript 和现有设计 tokens，没有引入数据库、同步服务、UI 框架或新依赖。本轮未推送，也没有更新 v0.1.0 标签或生成新安装包。

## 已接入的体验

正常路径默认在本机自动保存查询、必要搜索结果、场景、回答、问题草稿、判断版本、所选引文、来源时间和分支位置。标签栏的「路径」显示待保存、保存中、已保存、未保存或受保护；点击后才展开最近路径、立即保存、恢复、删除和新建非持久路径。详细说明不挤占默认地图；路径库与地图/Agent 面板按点击切换。

正常退出会等待有界的保存检查；启动新进程后恢复窗口/标签、当前步骤与选定分支，已关闭的正常路径也可从库中明确恢复。原始 Fetch 正文不落盘，重启后的阅读页显示来源/取得时间与重新获取入口；问答和对照保留旧回答及引文，但不冒充仍持有完整原文。明确重新提问或对照才取得新正文、形成新步骤，旧版本仍可回看。

网页节点先显示恢复提示，不自动打开地址、重新提交 POST 或运行 Agent。新进程生成新的 owner、连接凭据与文档身份；旧授权、填写提案、运行控制器和原生访问索引均不恢复。

删除需在路径库确认整条路径及其笔记；提交排除这条路径的新清单，清理其旧代文件和临时文件，关闭对应标签。旧写入不能在删除完成后重新插回路径；其他路径保留。保存失败时标签不会静默关闭，窗口关闭/应用退出会允许返回检查或明确放弃未提交更改。

「非持久路径」必须新建，任务数据不参与写入和恢复；不是把已经保存的路径切换成“私密”就宣称原记录消失。各标签目前仍共用网站资料档，因此**这不是完整隐私浏览**。任务文件仅在本机，未单独加密；删除任务不清除网站 Cookie、浏览器自身缓存、下载或另行导出的回执，也不承诺安全擦除。

## 存储边界与提交方式

新增 [存储契约](../prototypes/electron-m0/src/contracts/task-storage.ts)和[文件仓库](../prototypes/electron-m0/src/storage/task-repository.ts)。只按显式白名单序列化；排除原始正文、原生 pageState、网页字段、Cookie、密钥、权限对象、内部提示词与运行时实例。已保存任务的回答/笔记不随内存缓存释放被当作删除；保存格式允许显式缺失的可重取载荷，仍保留路径和版本元信息。

任务位于应用资料目录的 `tasks-v1`：`manifest.json` 是唯一提交入口；每代 `gen-<UUID>` 内按路径 ID 分别存任务。每份内容带 schema 版本，清单记录路径元数据、字节数、内容 SHA-256 和窗口引用。加载验证类型/大小、树的父子与选定分支、内容标识、来源位置、版本和文件哈希；拒绝目录跳转和符号链接。缺失或损坏的内容会隔离，未知格式或清单缺失时保留原件、停止覆盖，应用仍可继续浏览。

写入只有一个执行者，合并频繁更新。先写齐新代内容并同步文件，再写临时清单、同步后替换提交清单；确认完成后才显示已保存。只恢复清单指向的一代，不扫描备份自动“找回”已删除记录。提交后清理旧代；失败前的暂存文件尽力清理，清理失败可见。普通退出屏障最多等待 5 秒；异常退出只承诺最近已提交的一代。

具体额度：最多 **48 条路径**，单条任务 **2 MiB**，总任务载荷 **24 MiB**，单条路径仍为 **32 个记录节点**；不静默裁掉分支或个人判断。输入与正文缓存仍受既有独立预算约束。清单额外限制在 128 KiB；写新代期间可能同时存在旧代与暂存代，24 MiB 不是整个浏览器资料档的磁盘总上限。额度不足时旧提交不被覆盖，不将失败写成保存成功。

本轮对照的一手资料是 [Node 文件写入/同步接口](https://nodejs.org/download/release/v26.9.0/docs/api/fs.html#fspromiseswritefilefile-data-options)、[Electron 退出事件](https://www.electronjs.org/docs/latest/api/app#event-before-quit)和 [Session partition](https://www.electronjs.org/docs/latest/api/session#sessionfrompartitionpartition-options)。采用单写者、先内容后清单、正常退出屏障是 Grid 的实现决定；文件同步/替换**不被描述为跨平台断电零丢失保证**，任务不落盘也不等于网站资料档不落盘。

## 本机验证

macOS arm64、Node 26.12.1、Electron 45.2.1、TypeScript 7.0.2；隔离临时资料目录、合成 Search/Fetch/Model 和本机 HTTP 页面。没有使用个人 key 或外网模型。

本轮修复了异步启动的半初始化窗口、关闭中窗口阻塞保存、快速输入遇到滚动恢复时漏记草稿，以及长状态说明挤压窄窗口地图的问题。保存失败关闭保护也通过真实 UI/IPC 检查。多窗口脚本改用布尔就绪检查及保存的活动窗口，避免把桥接对象序列化或窗口焦点时序当作产品事实。

## 下一步与未验收项

第 5 步的本地实现与自动检查已覆盖跨正常退出的恢复、删除和非持久策略；第 6 步继续完整任务的 UX 精修、内容质量核对与真人试用对照。当前仅本机 macOS 验证；Windows/Linux 安装、真实断电、迁移未知新格式、完整屏幕阅读器体验和实际用户收益仍未验收。保存空间受保护时没有自动修复或覆盖原件，仍可普通浏览，但新的正常任务不能宣称已保存。
