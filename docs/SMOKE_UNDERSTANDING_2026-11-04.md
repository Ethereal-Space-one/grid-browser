# 4A 短总结与问这页：本地验收

日期：2026-11-04。依据：[主计划 §3.8](../PLAN.md#38-点击递进与链式地图2026-11-04-用户确认待产品实施)、[六步实施计划](./PATH_MAP_IMPLEMENTATION_2026-11-04.md)。这是当前源码的本地实现记录，既有 v0.1.0 标签和安装包未变化，没有推送或发布。

## 产品范围

- 搜索先返回可打开的结果。用户点击才发送前 10 条结果的摘要给模型，每条最多 1600 个 Unicode 字符；最多三句、360 字符的短总结填入固定高度区域，不推动列表。保留提供者顺序，标注“未核对原文”。失败、资料不足和停止不删除结果。
- 阅读页点击“问这页”进入独立状态，进入本身不联网；提交问题才调用模型。原页 A 的入口明确使用公开 Fetch 正文，不读取登录态网页、Cookie 或输入字段。公开正文不可用时不继续调用模型。
- 问答只发送这版公开正文最多前 16000 个 Unicode 字符和本次问题，不附加前次回答。输入范围可展开查看；Fetch 版本、时间、截取状态、回答生成时间保留。支持停止、草稿恢复、返回来源位置和原页。
- 每次提交建一个节点，回答完成只更新这个节点；返回缓存回答或总结不再次调用服务。旧分支保留，节点容量与 8 MiB 内容缓存沿用现有规则；缓存释放不删除拓扑，不隐式重新获取。

## 模型与权限边界

新增独立 Model 请求契约，复用 DeepSeek 适配器的 20 秒模型超时、15 秒 Fetch 超时、2 MiB 响应上限、取消与请求归属。原页首次提问可能依次等待 Fetch 和模型；没有无限等待或后台自动重试。当前使用最终回答，未接流式输出。

请求使用 `deepseek-flash`、关闭 thinking、`response_format: json_object`，不提供工具。应用验证完整结束标志、JSON 结构、输出长度、来源 ID 与逐字 quote；引用 URL 由应用从本次资料补齐。截断、空白、来源缺失或引文不匹配均拒绝作为成功回答。资料不足时明确说明。**逐字匹配只验证引用存在，不能证明每项结论被支持**；提示词也不能被视为已解决提示注入。

参数与 JSON 失败行为参考 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。Fetch 仍只取得原文，没有假设其接受 prompt。

新增入口复用可信 UI sender/main frame 校验，显式校验当前 owner/entry/正文记录。切场景、导航、停止、关闭和界面重载后的迟到响应不能复活回答。问答不增加 MCP 读取授权或网页动作能力；离开原页的既有撤权规则保持。

## 逐段检查

1. 在改动前保存当前源码快照，保留之前未提交的全部工作；核对主计划、实施表、现有 tokens 与 adapter。
2. 先接契约、受限模型、缓存和请求归属，再加原有状态与模型异常检查。最初普通环境不允许本机连接的 4 项检查，在允许临时本地连接后复跑全部通过；不是接口故障。
3. 实际运行生产 UI/IPC，检查结果先行、独立问答、一次提交一个节点、依据点击、返回位置、草稿、分支和取消。
4. 截图复核后缩减总结留白，避免完成状态挤占正文；修正截图等待逻辑，等待 UI 已显示答案且颜色过渡完成。来源节点不可用时禁用返回位置并说明。检查实际控件位置后修正窄窗口原页入口挤压，断言“问这页”、Agent 与至少 50 CSS 像素的地址输入区都在视口内，不只检查横向滚动。
5. 复跑既有地图、网页导航、标签、请求、路径状态、授权、填写、场景与视觉检查；最后再用最终问答源码更新报告与截图。

## 本机结果

环境：macOS arm64，Node 26.12.1、Electron 45.2.1。全部使用临时资料档和合成内容，不读取个人 key，不调用外网模型。原页测试拦截隔离资料档中的 HTTPS 协议，不使用真实登录页面。

| 检查 | 结果 |
|---|---|
| `npm test` | 46 项通过，含 7 项新增模型/问答边界检查 |
| `npm run test:e2e:understanding` | 9 组通过：固定总结、总结失败/停止、正文版本与依据、缓存/分支/草稿、错误引文/取消、归属拒绝、键盘/刷新/文本安全、公开 Fetch 范围、外观与对比度 |
| 路径栏/地图、网页导航、标签窗口 | 分别 10、16、13 组通过；原生导航 POST 仍仅为测试中明确提交的 2 次 |
| 请求生命周期、路径状态 | 分别 13、6 组通过 |
| MCP、受限填写、场景 | 分别 8、12、6 项/组通过 |
| 既有视觉检查 | 浅深色、320/375/414/768/1180 宽度及减少动态效果通过 |

新增界面检查覆盖浅深色 × 五场景 × 320/375/414/768/1180 CSS 宽度、150% UI 缩放，字段与非禁用来源按钮的采样文字对比度最低约 5.57:1；这是指定组合的 WCAG 比值检查，不是完整无障碍认证。新控件沿用系统字体及现有中性色/场景 tokens；标签、焦点、原生 Tab 顺序、减少动态效果均检查，未引入动效或 UI 依赖库。

被 Git 忽略的 `.local/understanding-e2e-report.json` 保存报告；`understanding-results-light.png`、`understanding-answer-light.png`、`understanding-answer-dark.png` 是生产界面合成内容的实际截图；`understanding.preview.html` / `understanding-states.png` 是八状态设计检查，不属于生产 UI。预期拒绝的负面检查会输出错误日志；脚本最终状态与退出码共同判断通过。

## 尚未验收

本轮没有真实模型内容质量、真人使用收益或 Fetch 站点覆盖率结论。真实调用已接入，但本地合成报告不替代真实 API 连通和内容人工核对；既有 live 脚本仍只验证先前 Search/Fetch 流程。

原页提问暂不能依据登录态/动态页面作答；公开 Fetch 文本可能与所见原页不同。尚无多轮对话记忆、来源对照、判断笔记或跨重启保存。Search/Fetch 内容权利、正式安全、签名分发、远端 CI 和新安装包均未因本轮实现而通过。
