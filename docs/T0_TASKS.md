# T0 真实浏览任务基线（v0.1）

> 2026-10-31。源自 [PLAN.md](../PLAN.md) 的 M0。这里定义任务，不填写尚未取得的用户结果。

## 执行方法

1. 在同一台设备、同一天、同一网络条件下，让参与者先用惯用浏览器完成一轮，再用 Grid 样机完成一轮；下一位参与者交换顺序。若某项样机尚未实现，记录“未实现”，不把外部搜索引擎页面算作 Grid 搜索完成。
2. 所有任务从新窗口或明确保存的起始状态开始。记录浏览器与版本、操作系统、屏幕尺寸、参与者匿名 ID、开始/结束时间、完成与否、错误、返回查找次数、重复查询次数、偏离任务次数。登录、上传和下载只用自愿提供的测试数据。
3. 任务的“完成”由可见页面或本地回执判定。涉及当前网页事实时，记录访问日期和当时来源；不把模型回答当作完成证据。
4. 本地夹具运行：`python3 scripts/serve-fixtures.py`，然后访问 `http://127.0.0.1:8765/`。它检验导航、表单、iframe、下载和 VP9/Opus 媒体；搜索、其他媒体格式和真实网站兼容还要在线测试。
5. 测量首个可用结果、原页打开和最终完成三个时间点；同负载报告 P50/P95 与完整进程树内存。没有样本量时只列原始观测，不提前给统计结论。
6. `prototypes/search-lab/` 单独用于搜索页信息层级评估：请观察参与者是否先发现结果、是否误把录制总结当成已核对事实、总结失败时是否仍会打开原页。它不是 S01–S06 的真实搜索完成记录。
7. A01–A04 优先让 macOS 开发者从常用 AI 编程工具经 Electron 原型的本机 stdio/MCP 桥接执行；记录首次连接步骤与耗时、授权页面读取、是否认出当前站点/目标/输入、暂停或接管是否在下一动作前生效。未实现桥接或真实动作时分别记“未实现”，不能把静态预览记成完成。原型结果只说明流程价值，正式闸门与可信预览在最终内核另验。
8. V01 先用本地 `media.html` 的自生成 VP9/Opus 视频与字幕重复操作，再在 G1 媒体矩阵中登记真实视频网站及其他编码格式；V02 先登记参与者同意使用的会议测试站和设备。记录浏览器安装包、系统、耳机/摄像头、权限和失败原因。当前样机未完成此项实测，不能把上游内核能力直接记为通过。

## 30 个任务

| ID | 用户任务（直接读给参与者） | 完成判据 | 类型 |
|---|---|---|---|
| N01 | 在地址栏打开 `https://www.wikipedia.org/`。 | 原站页面可交互，网址未变成查询。 | 在线导航 |
| N02 | 只输入 `developer.mozilla.org`，打开该网站。 | 自动补全安全协议并进入原站。 | 在线导航 |
| N03 | 从本地夹具首页进入第二页，再后退和前进。 | 两次导航均到正确页面。 | 本地导航 |
| N04 | 从夹具首页在新标签打开第二页，返回原标签。 | 两页同时存在，原页状态保留。 | 本地标签 |
| N05 | 在夹具表单输入 `T0-05` 后重新载入页面。 | 页面正常重载，输入状态按站点行为处理。 | 本地重载 |
| S01 | 查找 WebDriver BiDi 是什么，并打开 W3C 的原始规范。 | 能指出规范页面与其当前状态。 | 在线搜索 |
| S02 | 查找在 macOS 构建 Chromium 的官方步骤。 | 打开 Chromium 官方构建文档。 | 在线搜索 |
| S03 | 查找“WebMCP 目前是什么状态”。 | 打开官方说明，并说明是否可作为稳定依赖。 | 在线搜索 |
| S04 | 搜索“适合自己构建的开源浏览器”，找出两个项目的源码仓库。 | 两个可打开的仓库与差异理由。 | 在线搜索 |
| S05 | 搜索“浏览器 MCP”，澄清 MCP 指的是哪项技术。 | 参与者能解释自己选定的含义与来源。 | 歧义搜索 |
| S06 | 查询 Chromium 当前 stable 版本与发布说明。 | 来源、访问日期、版本号三者一致。 | 时效搜索 |
| R01 | 从 S02 的结果进入官方原页，找到构建命令。 | 可指出原页中的命令位置。 | 原页阅读 |
| R02 | 从 S03 的原页返回搜索结果，改写查询再搜索。 | 原查询可找回；修改无需从头输入。 | 返回与改写 |
| R03 | 比较 Chromium 与 WebKit 官方文档对多进程隔离的描述。 | 两个原始来源均可再打开，区别可复述。 | 多来源比较 |
| R04 | 在本地夹具中找到“橘色风筝”的完整原句并记下页面。 | 原句逐字正确，页面位置可复查。 | 原文核对 |
| C01 | 一边查 BiDi 规范，一边打开另一个官方浏览器文档，再回到原问题。 | 无需重复搜索就能继续原任务。 | 跨标签意图 |
| C02 | 中断 S04，先开新标签访问夹具，然后继续 S04。 | 原查询和已找到的两个候选不丢失。 | 任务恢复 |
| C03 | 同时保留三个来源，比较后关闭其中一个。 | 剩余来源与当前目标仍清楚。 | 标签压力 |
| O01 | 在本地夹具表单填入 `T0-01` 并生成回执。 | 页面显示“已记录：T0-01”。 | 动态表单 |
| O02 | 在夹具的嵌入页面输入 `T0-02` 并确认。 | iframe 显示“框架已确认：T0-02”。 | iframe |
| O03 | 从夹具下载测试文本并在本机找到文件。 | 文件内容和下载位置可核对。 | 下载 |
| A01 | 从常用 AI 编程工具经本机桥接读取当前夹具页面，找出“橘色风筝”所在位置。 | 记录首次接入步骤与耗时；用户能确认授权的标签与站点；文本可在当前页核对；无复制登录资料步骤。 | Agent 只读与连接 |
| A02 | 从 AI 编程工具让 Agent 准备在夹具表单填入 `T0-A02`，先查看预览，再允许执行。 | 执行前能指出站点、目标和拟输入内容；执行后真实页面显示正确输入或回执，预览不冒充结果；JSON 操作回执可导出。 | Agent 动作预览 |
| A03 | 让 Agent 连续完成两步夹具操作，在第一步后暂停并接管页面。 | 暂停入口可找到；接管后后续 Agent 动作不再执行，用户可继续手动操作。 | Agent 暂停与接管 |
| A04 | 让 Agent 预览一次夹具按钮点击，然后在确认前导航或改变目标。 | 旧预览失效并要求重新定位；不会在新页面或新目标上执行旧动作。 | Agent 预览失效 |
| V01 | 打开本地夹具 `media.html`，播放 30 秒，拖动进度、开字幕、全屏，再切到另一标签。 | VP9 画面、Opus 声音和字幕持续可用；操作后状态正确；格式与失败项有记录。 | 媒体播放 |
| V02 | 用测试账号进入预先登记的视频会议站，允许摄像头与麦克风，开始共享屏幕，然后撤销权限。 | 通话设备、共享和撤权按预期生效；站点、设备与权限提示有记录。 | WebRTC 与设备权限 |
| F01 | 断开网络后，继续使用本地夹具的导航与表单。 | 浏览器仍可用；在线失败有明确原因。 | 断网 |
| F02 | 禁用或不配置 AI 服务，完成 N03 与 S02。 | 基本浏览可用；搜索降级路径明确。 | 模型故障 |
| F03 | 仅用键盘完成 N01、N03、O01，并用屏幕阅读器检查地址栏。 | 焦点顺序清楚，输入与控件有可读名称。 | 无障碍 |

## 记录模板

先复制 `docs/t0-results.template.csv` 为被 Git 忽略的 `docs/t0-results.csv`，再逐行填写；不能把未运行任务预先写成通过。每个浏览器每个任务一行，允许附观察笔记与屏幕录制位置。原始参与者数据不公开；基线分析先看未完成原因，再看时间与重复操作，此时不设“提升百分比”目标。
