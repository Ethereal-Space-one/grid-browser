# 立项目标回查与真实宿主填写验证

日期：2026-11-03（北京时间）。按 PLAN.md §1–3 及 TECHNICAL_PLAN.md §6 验收。本次不把协议连通或自动脚本成功等同于真人体验达标。

## 从立项要求到这次检查

| 立项要求 | 本轮检查 | 边界 |
|---|---|---|
| 用户决定目标，模型不扩大权限 | 模型读取合成验证码并提出固定字段填写计划；无 MCP 确认/执行入口 | 仅本机测试页，非广泛网站操作 |
| 确认前看清来源、目标、输入及影响 | 预览分开展示客户端自报名称、页面地址、任务代号字段、拟填写内容及“不提交”说明 | 客户端自报名称不是身份认证 |
| 可暂停、接管 | 真实模型提案后通过 Grid 按钮暂停、恢复、确认；暂停期间字段保持空白 | 测试脚本代替人点击，不是用户研究 |
| 浏览与操作在同一会话 | 由 Grid 原页读取并填写同一字段，独立检查实际字段值 | 不复制 Cookie，仍只用合成页面 |
| 失败不伪装成功 | 宿主有总超时，报告同时要求成功读取回执、真实预览、实际填写及最终验证码一致 | 未跑通的宿主保留失败，不沿用历史通过结论 |
| 减少注意力与配置负担 | 主操作前置、手动测试入口折叠、面板限高，按需查看连接细节 | 普通用户连接流程仍偏开发工具，尚非发布级体验 |

## 发现并修正的体验问题

1. 旧预览把客户端、地址、内容、状态挤在一行，不利于确认。现拆成短段，填写值单独呈现，使用文本节点而非 HTML。
2. 最初改版的截图显示确认按钮被连接说明挤出可视区。已将待确认动作移到面板前部，并在真实宿主测试中断言确认按钮无需滚动即可看见。
3. 完成后仍显示“等待确认”会造成误解。标题按完成、暂停、失效、失败区分；完成明确为“已填写，尚未提交”。
4. 控制面板在矮窗口占比过大。面板高度上限为 350px，且不超过窗口高度的 44%，给原页保留空间；详细说明可滚动查看。

本轮截图仅能核查控制面板。原页填写通过 Electron 中实际页面字段值检查，不能把界面文案当成填写成功的唯一证据。

## 真实模型与失败记录

`npm run test:e2e:hosts:forms` 使用临时资料档，验证码仅在本地页面上，不在启动提示中。模型先请求只读授权，再读取、提出计划并查询状态。授权、暂停、恢复和确认由测试脚本在 Grid 中执行；全过程不提交表单。只保存状态与耗时，不保存模型原始输出或个人网页。

- Claude Code 已通过。调整按钮位置后单独复验也通过；后一轮从 CLI 启动到提案约 10.130 秒，到确认完成约 10.522 秒，整体退出约 14.780 秒。这些包含模型与网络时间，确认由脚本模拟，不是人类任务完成时间。
- Codex 首轮 90 秒内没有连接 Grid，没有读取或提案，按超时失败记录。独立 READY 最小请求暴露 WebSocket TLS 握手失败，反复重连后回退 HTTPS 才成功。不能把该问题归因于表单执行器；也不能据此宣称接入体验良好。保留首轮失败，并用可配置的 160 秒上限覆盖回退路径复验。复验通过：首次连接约 117.024 秒，首次读取约 121.837 秒，提案约 127.009 秒，脚本确认完成约 127.389 秒，整体约 146.230 秒。报告时间为北京时间 23:30:17。该延迟不能视为良好的首次使用体验，首轮超时仍保留。
- 首轮测试脚本另有空连接 ID 比较错误，误读尚不存在的动作状态；已修正。这次错误不计作产品填写成功或失败证据。

报告在 `.local/hosts-form-e2e-report.json`（最近一次运行），控制面板截图在 `.local/{host}-form-preview.png`。CLI 正常退出码本身不代表通过：超时、无读取、无预览或字段不一致均使测试返回失败。

## 仍需用户验证

- 未提示情况下，用户能否准确复述“谁、哪页、哪个字段、填什么、是否提交”。
- 实际按键/点击数、首次连接时间、确认负担，与惯用浏览器对照。
- 真实用户能否成功拒绝、暂停或接管，失败后继续原本浏览任务。
- 更换页面、不同窗口尺寸、屏幕阅读器、长文本、框架表单和完整对抗测试。

以上不能用两个宿主或内部截图自评代替。当前仍是 M0 价值原型，不是最终内核安全验证。
