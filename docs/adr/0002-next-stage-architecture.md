# ADR 0002：下一阶段模块化与架构选择

日期：2026-11-04。状态：**分阶段实施中；请求/上下文及窗口/标签内存状态已本地通过，完整退出恢复与其余实验、最终内核/发布安全未通过。**

依据：[PLAN.md](../../PLAN.md)、[技术计划](../../TECHNICAL_PLAN.md)、[架构调查及来源](../ARCHITECTURE_RESEARCH_2026-11-04.md)。当前实现基线为 `34f4f67` / `v0.1.0`。本 ADR 不改变已有版本标签。

## 问题与约束

v0.1.0 已连接真实搜索/正文、五场景提取、原页和受控本机 MCP，但仍是单页原型。状态分散在主进程全局变量与 renderer，权限、网络和 UI 编排集中，尚无完整日用浏览器或正式发行能力。继续直接加功能会放大旧请求覆盖、上下文串联、资源销毁和动作状态不确定的问题；直接换内核也不会自动解决它们。

用户优先级是自主搜索、连续阅读、可控 Agent 与有品味的低负担界面。必须保持网址直达不依赖 AI、结果先可用、五种显式场景、A/B 都可比较、人能拒绝/接管、凭据不发给远程页面。真人价值基线、通用网页动作安全、安装升级及 G1 尚未通过。

## 拟采用的决定

1. **下一阶段继续 Electron + TypeScript，渐进拆分。** 先在原型目录内分出 `contracts`、纯业务用例、Browser Host、providers、renderer 和 stdio 适配层，不先迁移仓库或引入多语言构建。现有模块只有验证后才移动，应用始终可运行。
2. **宿主拥有状态和权限。** 窗口、标签、导航、文档身份、授权、动作执行、凭据及恢复由 Browser Host 裁决；UI 和 MCP 调用相同用例，不能各自维护另一套浏览器状态或执行权限。主框架与可信来源、请求/响应 schema、大小、时间和并发限制在接口边界验证。
3. **每次异步工作都有不可变上下文。** 搜索、Fetch 与提取绑定运行 ID、所属标签、代次、查询、场景和来源版本；取消传到网络，完成后仍检查是否当前有效。UI 渲染宿主快照，旧响应不更新宿主或界面。新搜索未完成时保留旧结果。
4. **服务适配与进程选择分开。** Search、Fetch、Model 使用独立接口和合约测试；纯用例依赖端口，由入口注入 Electron/提供者实现。辅助进程只有在故障/负载实验支持时引入，可继续 TypeScript；凭据与出站策略建议留在宿主网关，worker 默认没有真实浏览会话、WebContents、Cookie 或动作接口。Node 进程不被描述为天然 OS 沙箱。Rust/C++/Protobuf 均不作为此前置条件。
5. **读取、提案、执行确认分权。** 模型/客户端可请求读取或提出计划；只有可信 Grid 界面可生成执行确认。动作绑定连接、页面/框架/目标、相关版本、人工输入栅栏与期限。未发送可取消；已发送而结果无法确定则 `unknown`，停止后续步骤并只读核对，不自动重试写操作。通用写动作在实验通过前保持关闭。
6. **恢复最小化，分发独立验收。** 偏好/恢复元数据先版本化原子文件；历史查询需求成立再引入 SQLite；正文、凭据与回执分开。跨崩溃追踪的写动作先落最小执行记录，未终结记录重启后为 unknown；恢复不恢复授权或自动执行。生产 MCP 连接器与 RunAsNode/fuses 同时决策；正式包做签名、公证、跨机器安装和升级演练。

以上是分阶段目标，不能把目录或类名视为已经全部满足。[第一切片记录](../SMOKE_REQUESTS_2026-11-04.md)和[标签切片记录](../SMOKE_TABS_2026-11-04.md)明确当前实现与未完成项；Window/TabRegistry、每标签内存导航/位置、销毁及单实例已本地验证。完整应用恢复、动作 unknown 与执行日志、第二提供者/辅助进程及分发仍待实施。

## 选择依据与替代路线

| 选择 | 原因 | 重新评估条件 |
|---|---|---|
| 渐进模块化，而非整体重写 | 可保留已有真实链路，逐项验证当前发现的状态/权限问题 | 分离后仍有宿主 API 的硬性能力缺口 |
| 继续当前 UI 技术及 tokens | 场景/结果/阅读界面已有回归基础；换框架不是已证明的用户收益 | 具体组件复杂性、可维护性或无障碍问题需要新方案时做小实验 |
| CEF 作为有条件原生候选 | 可以研究宿主控制，但仍有浏览器 UI、分发和系统集成工作 | Electron 被必需任务阻断，CEF 相同切片证明能解决 |
| Chromium fork 暂不实施 | 需要承担补丁和持续安全发布，当前没有必要性及维护演练证据 | 价值门、能力缺口、人员责任、更新/回归和独立 ADR 全部成立 |
| WebKit/Tauri 不新增并行产品 | 当前资源用于既有纵向链路；系统 WebView 的平台差异仍需实测 | 用户目标改变，或新证据证明它更能满足已确定任务 |
| 不采用双内核或浏览器 headless 副本 | 同一会话和权限一致性尚未证明，不能靠复制登录态完成目标 | 存在必要任务并能验证资料档/权限/动作一致性时另作 ADR |

Electron 的官方进程/安全文档、Min 生命周期代码、BrowserOS 的浏览器/Agent 分层，以及 CEF/Tauri 的接口说明支持调查中的事实；它们不证明 Grid 的性能、安全或用户收益。完整链接和核对范围见 [调查 §3](../ARCHITECTURE_RESEARCH_2026-11-04.md#3-从一手资料和相关项目学什么)。

## 实施顺序与验收

| 顺序 | 最小交付 | 退出条件 |
|---|---|---|
| 1 | 共享 schema；搜索/阅读/提取上下文；宿主取消和代次；调用方校验 | 慢旧请求、切场景、返回、关窗不会改写新状态；原有路径继续通过 |
| 2 | Window/TabRegistry、每标签导航/结果/滚动状态和销毁；单实例策略 | 多标签不串查询/授权；关闭重开和崩溃恢复可预测；旧授权不恢复 |
| 3 | 动作状态语义、失效条件、发送后 unknown 和对账 | 撤权、人工输入、节点替换、导航/iframe、超时、进程退出均有可判读结果；不越过本地实验范围 |
| 4 | 第二检索源及有边界的 providers；可选辅助进程试验 | 取消/故障不阻塞浏览；请求/响应超限被拒；是否独立进程有实测依据 |
| 5 | 连接器/fuses、标准打包签名更新、实际包兼容矩阵 | 外部机器安装与 N→N+1 升级、key/配置迁移、撤销和基本任务可复验 |
| 6 | 汇总 R1–R6，提交 G1 正式选择记录 | 必需能力、用户任务和维护演练有证据；阻断项没有用综合评分掩盖 |

## 后果与剩余风险

收益是假设：模块边界可降低改动牵连、保持界面连贯，并为内核选择提供可比较用例；需要后续代码和实验验证。代价是新增显式状态、契约与回归用例，短期会减少新功能数量。Electron 宿主依然是高权限组件；同一用户恶意进程、页面注入、广泛站点兼容和安全更新不因拆模块自动解决。

后续若实验否定当前接口或运行时，应更新本 ADR 的状态和证据。只有 G1 正式记录通过，才把候选改称最终路线；A/B 产品选择、公共 relay、内容使用权和 `.lattice` 仍按主计划各自决定。

2026-11-05 接续实施：[第 6 步完整任务精修/自动验证](../SMOKE_JOURNEY_2026-11-05.md)完成现有模块边界内的 UX 整理及独立包验证，未新增框架或服务。75 项本地、四进程恢复和实际包两次启动已检查；原始正文与权限仍不恢复。真人试用按用户要求交接，内容质量和用户价值未通过，因此架构顺序 2 的真实任务出口仍开放；受限动作结果核对可接续实施，不以内部检查代替价值验收。
